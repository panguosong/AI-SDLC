# AI-SDLC 开发与发布合同

本约定只定义 AI-SDLC 仓库自身的普通开发与发布流程，不为普通用户项目增加治理负担。

## 开发边界

- 仓库源码是本地开发的控制实现，使用 `uv run ai-sdlc ...` 执行治理和验证。
- 每项变更使用独立分支或 worktree，保持变更范围可审查。
- 代码合入前运行相关测试、完整约束检查、lint 和构建验证。
- 不把本地凭据、运行缓存、临时证据或用户项目状态提交到仓库。

## 保留的复核能力

量化 Loop 沿用以下复核与关闭边界：

1. Local PR Review 在提交前调用独立本地代理检查当前 Git 变更。
2. 代码精简分析只给出建议，可因正确性和交付价值灵活突破，不阻断 Loop 或发布。
3. Requirement、Design Contract、Implementation、Frontend Evidence、Local PR Review 五类结果由 CLI 按内容选择最多两种专家角色，当前宿主 Agent 为每个角色自动启动独立只读上下文；专家只审查与 `input_digest` 同次读取返回的 `review_snapshot`，不得重新打开可变工件路径；同一结果最多一次修复后复审。

宿主 Agent 必须消费 `loop review` 返回的 `expert_roles`、`expert_reasons` 与 `round_number`，自动调用 `loop review-record`，不得要求维护者手动触发专家或搬运结果。宿主无法提供独立上下文、必要工具或有效判断时，必须报告阻塞，不得由作者自行给出 PASS。专家上下文和身份只存在于当前对话；框架仅在原 Loop 目录保存 `review-outcome-round-1.json` 和至多一个 `review-outcome-round-2.json`。系统不创建第三轮结果、review session、ledger、certificate、attestation、authority/store、Shadow/Enforce 激活状态或第二套 close 流程。

`v3.1.0` 的新量化实例覆盖五个 Loop、六个评分视角：需求、设计合同、实施方案、代码成果、前端证据、交付就绪。宿主根据普通 `run` 的 Next 准备冻结输入、候选和独立判断，框架复算预测评分并检查有限成本准入；用户不手填 JSON、分数或预算。实际产物仍由原生门禁和实际 R1/R2 判断决定是否关闭，预测高分不能替代浏览器、测试或真实审查证据。旧实例不迁移、不重置合同和预算；已退役的历史 continuation 不恢复执行。

## Pull Request

- PR 必须说明目的、范围、测试结果和剩余风险。
- Local PR Review 的验证证据必须在动态专家复核之前记录，最终报告只在复核无可操作问题后生成。
- 专家不可用、超时或返回无效结果时，Loop 保持 `needs_review`；不得把失败解释为通过。
- 有发现时由原实现代理修复，并只允许一次复审；仍有问题则停止并报告，不进入无限对抗循环。
- 通过后由当前代理调用既有 close，再走普通 CI、分支保护和合并流程。

## 普通发布流程

新用户手册从 `v3.0.0` 之后的首个版本开始执行
[`新用户手册发布标准`](user-guide-release-standard.zh-CN.md)：必须覆盖全新空项目与已有项目、在线与离线安装、Windows/macOS/Linux 的 12 条自包含路线。任一路线缺失、不能从全新终端独立执行，或没有对应真实环境验证，均阻塞发布。

发布使用 `.github/workflows/release-build.yml` 和 `.github/workflows/release-artifact-smoke.yml`：

1. 从已通过保护检查的 main 提交创建精确版本 tag。
2. 为该 tag 创建新的空 Draft Release，不复用历史 Draft。
3. 构建 wheel、sdist 和三个目标平台的离线包。
4. 在 Windows、macOS、Linux 执行安装与 smoke。
5. 仅把通过 smoke 的三个离线包及其三个 checksum 上传到 Draft Release。
6. 下载 Draft 的六个资产并核对名称、sidecar 与 SHA256；制品或构建 smoke 失败保持 Draft，不改写 tag。只读 token 无法读取 Draft 时，不能把可见性失败记为通过，也不增加权限或盲目重试；保留构建 smoke 与资产校验证据。
7. 由明确授权的维护者重新核对 main、精确 tag、Draft 和六资产身份后发布为 latest，等待发布事件触发的三平台制品 smoke；再分别手动触发 `windows-user-guide-e2e.yml` 与 `posix-user-guide-e2e.yml`，输入 `tag=v3.1.0`。两份用户指南 E2E 不会由 release 事件自动触发，全部通过后才宣布发布完成。

发布流程不生成 Release Proof、Permanent Certificate、generation burn、release attestation 或额外 authority 指针。GitHub Release、tag、普通 CI 和分支保护是发布所需的现有平台能力。

## 当前基线与发布身份

本公开源树以已发布 `v3.1.0` 为代码基线。重新导入源树不创建或补发历史 Release，也不继承历史提交的 Close 身份。正式稳定版本以精确 tag、GitHub Release 和该提交的实际验收结果为准。



发布变更必须同步检查 `README.md`、`USER_GUIDE.zh-CN.md`、`packaging/offline/README.md` 和 `docs/pull-request-checklist.zh.md`。项目地址固定为 `https://github.com/SinclairPan/Ai_AutoSDLC`。

本次目标正式离线制品名为：

- `ai-sdlc-offline-3.1.0-windows-amd64.zip`
- `ai-sdlc-offline-3.1.0-macos-arm64.tar.gz`
- `ai-sdlc-offline-3.1.0-linux-amd64.tar.gz`

构建必须生成 `SHA256SUMS` 和每个归档对应的 `.sha256` 文件。

本次发布还须验证真实已安装 wheel 与 sdist 构建的 wheel 能走完五 Loop 的既有流程和普通 Close，并绑定候选、实际导入位置与回执；不能用源码环境通过或历史包的结果代替。测试通过只证明相应协议与反例，不能据此宣称预测评分的模型效果、节省成本或全局最优已经获得验证。
